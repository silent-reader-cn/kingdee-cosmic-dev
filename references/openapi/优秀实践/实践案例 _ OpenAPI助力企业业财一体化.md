# 实践案例 | OpenAPI助力企业业财一体化

# 1 小编推荐

集团型公司往往面临着**“各子公司独立运营、数据在业财系统相互独立存储、独立维护，彼此间相互孤立”**的情况，导致集团**管理效率低下、****决策分析滞后**等问题。

那么，今天就为大家带来**“OpenAPI助力企业业财一体化”**的案例实践，一线真实案例，亲测有效~

撰稿人：金蝶—张博。

# 2业务背景

## 2.1 产品相关的业务现状

客户为大型央企，主营业务包含先进制造与技术服务、医药医疗健康、贸易与工程服务等。由于业务不断扩张，企业内部业务系统日益增加，需要对常用数据进行**集中化管理**，以**统一数据标准和口径**，对服务进行**统一治理**。

依据**财务一体化建设目标**及系统集成需要，我们和客户共同梳理出**45项**通用数据，涵盖了总账、应收应付、资金等模块的常用业务场景。对接系统包括客户方的主数据系统，以及成员公司多种异构系统，大部分接口对接数据均达到了**百万量级**。

![](https://vip.kingdee.com/download/010930bf217862864a0b8d5ad93413be643b.png)

业务现状图

## 2.2 客户痛点分析

**业财数据缺乏关联性。**数据在企业内部各业财系统**独**立******存储、独立维护、彼此间相互孤立**，系统间数据**“同名不同码，同码不同名”**的情况大量存在，数据连贯性差，跨部门协作效率低。

在建设财务一体化平台过程中，共涉及集团和成员公司至少**26套**系统，且除客商主数据外，基本没有统一的数据管理系统支撑，各成员单位系统间各自为政，其中，数据定义、数据准入规则、校验机制、管控流程等无统一标准。
**数据统一管控类型有限。**目前实现统一标准化的数据类型有限，大多数数据按需分散维护管理。

## 2.3 客户诉求

- 受财务视角对主数据**需求场景**、**范围**的限制，需进一步扩展数据信息的完整性管理；
- 需要统一考虑并建立数据标准，加强对业务财务一体化应用及**统一经营决策分析**的支撑作用；
- 需要统一考虑主数据管理体系，构建**特色数据管理体系**、**统一数据管理平台**，并实现数据管理有效协同；
- 需要统一考虑数据集成方案，实现数据的**线上集成交互**， 为**数****据集中化管理**奠定基础；
- 拓展技术平台功能，以支撑集团内数据**高并发**，提升系统性能，实现数据治理，提高用户满意度。

# 3 解决方案
金蝶AI苍穹开放API标准服务，可以整合**端到端业务循环**及外围系统集成需求、实现相关业务链上**17个**系统间的集成、融合方案将满足**171项**业务接口(未包含多版本情况)，并按**“1+4”模式**进行集成域的分类划分。

![](https://vip.kingdee.com/download/01092156624c9448428297eda9b0a8490dc5.png)

项目方案图
该方案使用到金蝶AI苍穹开放API，主要体现在以下**4个**方面：

**1、权限管控。**

对接不同系统采用不同的鉴权方式以及不同颗粒度的权限管控：

对于与**主数据集成**，是**系统与系统间**的集成方式，主数据系统需要对接多种异构系统。所以，以主数据对接标准为主，采用苍穹的**【基本认证】**方式与主数据平台进行对接。通过对**API授权**和**IP白名单**的形式保证接口的安全性。

![](https://vip.kingdee.com/download/010943c02d0b8c5d4681a46933e0129a0c4e.png)

【基本认证】-API授权和IP白名单配置
对于和**成员公司**对接，苍穹作为接口的提供方，采用的是**“AccessToken认证”**的认证方式。通过对**API授权**和**IP白名单**的形式保证接口的安全性。另外，对每家二级公司单独分配应用，做到每家公司的密钥独立更加安全。

![](https://vip.kingdee.com/download/0109359b4c8b0e8d4d3da5c619ab465c0b07.png)

苍穹注册的外部第三方应用列表
**2、中间表。**

和**外部系统**对接是**http协议**，接口交互形式即使用**restful接口对接**，相互调用对方的接口，以**ip+端口号+方法路由形式**构建一个url。客户对数据安全性要求较高、数据交互需要有记录，并要求接口对接以**中间表形式**进行系统对接，即**下发上报不直接走接口通信**，而是对**数据库**进行读写操作。

当任务完成时候，上报将此任务状态改为**“已经完成”**。中间表机制**既能保证数据安全性**，又能对异**常接口报文进行重试补偿**。

![](https://vip.kingdee.com/download/010953a335baa1764780a728c3d809e92af5.png)

中间表流程图
**3、管理API。**

通过开放平台OpenAPI管理接口，从接口创建→测试→发布→禁用→下架的全生命周期管理。不同阶段的接口可通过API状态进行区分，如下图所示：

![](https://vip.kingdee.com/download/01099341a571a89d49d58c31944e492d125b.png)

接口的全生命周期管理

![](https://vip.kingdee.com/download/0109daf55251eddc41a7aaa4bef5a04ed8bb.png)

不同阶段的接口API状态
**4、自定义API开发。**

通过Java插件开发，并在开放平台通过简单的接口配置后，系统**自动解析出入参数**，可以快速、便捷地生成自定义API，并用于处理复杂业务场景。

用户可预先定义**类**和**方法**，在开放平台通过简单的接口配置后，系统自动解析定义好的**请求参数**和**返回参数**，快速生成自定义接口。

![](https://vip.kingdee.com/download/0109ac0b22220c5b4283883bf67bb2c04230.png)

自定义API接口

# 4 方案的可推广价值

1、**灵活、易用**。API2.0自定义注解API，支持复杂业务自定义逻辑，Spring主流注解时校验，通过不同的鉴权方式，可以适配更多的异构系统，丰富的报文格式：支持**JSON/XML，RestFul**及**WebService Soap协议**。

2、**安全**。通过分配第三方应用将**21家**二级成员公司的API访问权限和访问安全得以管控，保护企业数据安全。

3、**监控**。日志（故障定位）、统计分析可以对集成结果和异常进行分析。

通过金蝶AI苍穹开放平台OpenAPI服务解决方案，客户将**业务数据与财务数据完成打通**，**数据流实现了闭环**。从应收到付款等多方面提升**企业不同部门的协作效率**和**管理水平**，**降低跨部门协作难度**，为企业**积累核心数据资产**，以及未来管理的优化提供了**基础数据**。
