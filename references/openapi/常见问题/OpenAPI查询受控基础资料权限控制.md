# OpenAPI查询受控基础资料权限控制

## 1 问题描述

**场景一：数据越权**

通过 OpenAPI（API 2.0）查询受控基础资料（如供应商、客户等）时，返回结果未按管控策略进行过滤，可能导致用户查询到本不该有权限看到的数据。

**场景二：参数缺失报错**

使用 RESTful API 查询受控基础资料时，提示以下错误：使用组织参数 [orgIds（bos_bdCtrl_useOrgIds）] 为空。

---

**补充说明：什么是受控基础资料？**

受控基础资料是指**被管控策略约束、带有创建组织的**基础资料。管控策略决定了哪些组织能使用哪些基础资料，以及以什么规则进行共享或分配。典型的受控基础资料包括：供应商、客户等。

## 2 问题分析

OpenAPI 查询权限默认校验**组织权限、功能权限 、数据规则**，**不会自动校验管控策略**。因此，即使已经为受控基础资料维护了管控策略，通过OpenAPI查询时也不会生效，导致查询结果不受管控策略约束。

## 3 解决方案

**步骤一：**在公共设置中开启 "**数据查询权限全量校验**" 开关。

开启后，OpenAPI 查询数据时将同时校验：组织权限、数据规则、基础数据管控策略

**路径：基础服务云 - 公共设置 - 系统参数。**

![上传图片](https://vip.kingdee.com/download/0100ff35bc93e6dd41f2be565b7e1829ec5f.png)

**步骤二：调用时传入使用组织信息**

查询受控基础资料时，需要传入使用组织信息，方式如下：

| **传参位置** | **参数名** | 数据类型 |
| --- | --- | --- |
| 请求头 | `X-BD-CTRL-ORGIDS` | 数组 |
| 请求参数 | `bos_bdCtrl_useOrgIds` | 数组 |

说明：**RESTful API默认全量校验**，无需额外开启开关，直接**通过请求头传参**即可。

## 4 常见问题

Q：为什么之前没开开关也能正常查询？

A：关闭开关时，系统仅校验组织权限和数据规则，不校验管控策略。如果数据规则本身已覆盖了权限控制，查询结果可能看起来"正常"，但实际上管控策略并未生效。建议开启全量校验以确保权限控制完整。

Q：开关开启后，所有 API 查询都会受影响吗？

A：是的。开关开启后，所有 OpenAPI 查询都会同时校验管控策略。如果部分接口不需要管控策略校验，建议按需评估是否开启。

Q：RESTful API 和 API2.0 有什么区别？

A：RESTful API 默认全量校验，始终会校验管控策略；API2.0 需要通过上述开关来控制是否校验管控策略。

## 5 操作总结

1. 进入公共设置，开启 "数据查询权限全量校验" 开关
2. 调用查询接口时，通过请求头 X-BD-CTRL-ORGIDS 或请求参数 bos_bdCtrl_useOrgIds 传入使用组织信息
3. 验证查询结果是否符合管控策略预期
