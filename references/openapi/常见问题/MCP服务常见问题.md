# MCP服务常见问题

### 本帖汇总MCP服务常见问题，涵盖集群级MCP服务和账套级MCP服务（苍穹V9.0）。使用前请先确认苍穹版本：低于V9.0 则为集群级MCP服务。

## 1 Token认证问题

### 1.1 调用 MCP 工具时返回 401 未认证错误，是什么原因？

> 401 错误通常由于token过期或未传入 token 导致。access_token有效期固定 2 小时，需重新登录获取新 token。

### 1.2 调用 MCP 工具时返回 403 权限不足错误，是什么原因？

> 403 错误通常由于第三方应用的权限不足导致。解决方法：登录ERP系统，路径：开放服务云 - OpenAPI - 安全策略 - 第三方应用。查看第三方应用（灵基第三方应用编码为kwork），是否拥有该MCP服务关联的API的访问权限。

### 1.3 若灵基侧维护了正确的mcp.server.appId 和mcp.server.secret，获取到cosmic_mcp_token后提示错误码-32001，Unauthorized MCP access，或维护了正确的第三方应用如kwork和对应的appSecret，但是仍然返回401认证错误是什么原因？

> 高版本 Nginx 默认过滤带下划线的请求头参数，可能导致 `cosmic_mcp_token` 或 `access_token` 被丢弃。解决方法如下：
>
>
> 1. 打开 `nginx.conf`，在 `http` 块中添加：
>    ```
>    underscores_in_headers on;
>    ```
> 2. 保存后重启 Nginx 。

## 2 服务注册与状态问题

### 2.1 MCP 服务导入/新增后一直处于“待注册”状态，未自动发布？

> 系统每 5 分钟自动全量扫描并注册一次，一般等待5分钟内即可完成注册。若超过 10 分钟仍未发布，请检查：
>
>
> 1. MCP镜像是否已部署，环境是否存在mcpweb节点，若存在，mcp服务是否正常运行。
> 2. 苍穹版本低于 V9.0，且菜单为【集群级MCP服务】时，请检查：a. 通过Monitor日志搜 **OpenApiMcpProvider**，确认本集群MCP网关注册服务的目标数据中心。b. 只有被扫描的数据中心下的MCP服务会更新为**已发布状态**，其他数据中心状态不变，若集群内各数据中心MCP数据一致，则各数据中心MCP服务均可调用。

### 2.2 MCP 服务注册状态变为“失败”，如何处理？

> MCP 服务注册失败，常见原因包括 API 不存在或状态异常，以及 MCP 服务不可用。可按以下步骤排查：
>
>
> 1. 在「MCP服务」列表中找到失败的服务，查看异常日志字段，了解具体失败原因。
> 2. 根据日志提示修复问题（如API不存在、参数格式错误等）。
> 3. 修复后点击[重置注册状态]按钮，将服务重置为“待注册”，等待系统下次自动扫描重新注册。若多次重置仍失败，请联系平台管理员或研发人员排查MCP服务日志（Monitor日志搜**OpenApiMcpProvider**）。

### 2.3 服务状态为“已发布”，但灵基侧工具列表拉取的工具数量与预期（ERP侧）不符？

> 根据苍穹版本，通过Monitor日志检索对应关键字：
>
>
> | 服务类型 | 版本条件 | Monitor日志关键字 |
> | --- | --- | --- |
> | **集群级MCP服务** | V9.0以下 | `OpenApiMcpProvider` |
> | **MCP服务** | V9.0及以上 | `McpAccountTool` |
>
> 逐项核对以下 5 个要点：
>
> **1. 核查工具运行状态**
>
> 已下架、失败状态的工具不会展示在工具列表中。请前往「MCP 服务」管理页面核对工具服务状态。
>
> **2. 确认是否为标品预置 MCP 服务**
>
> 标品预置的 MCP 服务，脚本中 MCP 服务的状态为**待注册（UNPUBLISH）**。MCP 网关不会重复扫描注册状态为已发布（SUCCESS）的 MCP 服务。
>
> **3. 注册等待时间**
>
> 手工新增或导入 MCP 服务后，系统存在扫描注册延时。建议等待 **5 分钟**左右，等待注册完成。
>
> **4. 请求头参数**
>
> 调用工具列表接口时，请求头必须同时携带：
>
>
> 1. `cosmic_mcp_token`
> 2. `erpAccountId`（账套级 MCP 服务**必传**）若缺失 `erpAccountId`，会出现返回空列表，或仅返回部分非 API 类工具的问题。
>
> **5. 校验数据中心正确性**
>
> 工具列表按账套做数据隔离，传入错误的账套 ID 仅能返回该错误账套下的工具数据。此外，集群级 MCP 服务若默认扫描其他数据中心，**当两个数据中心中系统内置的 MCP 服务不一致时**，也可能导致结果差异。

## 3 配置与接入问题

### 3.1 erpAccountId（数据中心 ID）在哪里获取？

> 1. 通过 MC 管理中心：登录苍穹 MC 管理中心 → 租户列表 → 租户，点击租户详情可查看数据中心 ID。
> 2. 通过第三方应用配置页：如在第三方应用列表界面，点击按钮【更多】-【当前账套信息】，可查看当前数据中心 ID。

### 3.2 在智能体中配置 MCP 服务后，工具列表加载正常，但调用业务 API 时报错？

> MCP工具加载需要传入cosmic_mcp_token，业务 API 调用需要 access_token，两者相互独立。若工具列表正常但业务调用失败，所以重点排查 access_token：
>
>
> - access_token 是否过期：有效期为 2 小时，过期后业务调用会返回认证错误（401）。
> - access_token 对应的用户是否有权限：access_token关联具体业务用户，若该用户无对应单据或模块的操作权限，调用会返回业务权限错误而非认证错误。
> - erpAccountId 与 access_token 是否匹配：两者必须属于同一账套，跨账套使用会导致认证失败。
> - 直接验证 API 可用性：通过Postman携带 access_token直接调用目标 API，确认 API 本身可正常访问。

### 3.3 有些工具被标记为 sensitive（敏感操作），调用时多次确认无法删除，怎么处理？

> **高风险操作二次确认流程：**标记为 **敏感（sensitive）** 的工具属于高风险操作，调用时需要经过二次确认：
>
>
> - **第一步：首次调用**调用工具后，MCP网关可能返回 `MCP_CONFIRMATION_REQUIRED` 错误，并附带 `confirmationToken`或进入了流程循环。
> - **第二步：二次调用**将 `confirmationToken` 放入请求参数的 `_meta` 中：然后重新调用同一工具。
>   ```
>   params._meta["bos.mcp.confirmationToken"] = confirmationToken
>   ```
> - **若仍然无法执行，可以尝试要求智能体走原生MCP协议调用工具。**

## 4 服务发布与管理问题

### 4.1 租户新增 MCP 服务时（苍穹V9.0以上）无法选择标品 API，只能选二开API，这是为什么？

> 设计核心目的：**保证MCP与API保持一对一的对应关系**，避免因MCP服务数量膨胀导致网关缓存过大而影响系统性能。
>
> 具体规则如下：
>
>
> - **租户自建 MCP 服务**：仅允许开放二开 API，防止租户越权暴露标品接口。
> - **标品 API 发布为 MCP 服务**：须由金蝶标准开发商以「系统内置」来源发布。

### 4.2 工具名称按规则自动生成后超过 55 字符被截断，导致名称含义不清晰，怎么处理？

> - 工具名称支持手动修改。在「MCP 服务」列表中找到对应服务，将其改为更简短、语义清晰的名称。
> - 推荐命名风格：`{domain}_{module}_{action}`，将 `{apiuri}` 替换为更易理解的 action。
> - 命名重要性：工具名称是智能体识别和选择工具的关键依据，直接影响大模型的调用准确性。

### 4.3 已发布的 MCP 服务，关联的 API 发生变更（如新增参数），如何同步更新？

> **1）自动更新机制**
>
> API 变更后，对应的 MCP 服务注册状态会自动变为 **「待更新」**，系统在下次扫描（约 5 分钟内）会自动重新注册并同步最新的 API 定义，**无需手动操作**。
>
> **2）手动触发方式：若 5 分钟后状态仍未更新，可手动操作：**
>
>
> 1. 点击 **「下架」** 按钮
> 2. 下架后点击 **「重置注册状态」**，触发重新注册流程
>
> **3）标品更新说明**
>
> 若标品更新了 API 字段，需将对应 MCP 服务脚本中的状态改为 **「待注册（UNPUBLISH）」**，客户端 MCP 网关在自动扫描时才能更新 MCP 服务信息。
