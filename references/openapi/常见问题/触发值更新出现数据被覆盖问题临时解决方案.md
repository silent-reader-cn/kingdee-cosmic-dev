# 触发值更新出现数据被覆盖问题临时解决方案

## 1、问题描述

**示例场景一：**

完工入库单更新API开启的值更新，在请求参数里面给“仓库”，“仓位”赋值，值更新逻辑：当给仓库赋值时，会清空仓位，由于平台赋值是随机的，当先给仓位赋值时，再给仓库赋值时，就会出现这种情况，**调用方明明传了仓库仓位，但是最终仓位为空，导致接口调用失败**。

**示例场景二：**

新增接口里面如果参数里面设置了新增时触发值改变事件，业务单据如果仓库设置了仓位，新增时仓库填了值然后会提示仓位必填，**但是接口请求参数里面仓位这个字段是有值的，再将新增时触发值改变事件改为false，那么同样的json调用接口就不报错了**。

## 2、问题原因

**目前值更新赋值的处理是随机无序的，故可能出现先处理了B再处理A，导致B的值更新逻辑被覆盖问题。**

## 3、解决方案

### 3.1 长期解决方案：

待平台提供自定义操作参数保证原报文字段顺序，避免触发值更新时的无序问题。

### 3.2 临时解决方案

采用[**扩展插件**](https://vip.kingdee.com/knowledge/specialDetail/272110040385964032?category=272111020880021504&id=555710197700574720&type=Knowledge&productLineId=40&lang=zh-CN)，干预数据格式转为linkhashmap进行处理，插件实现逻辑：

![上传图片](https://vip.kingdee.com/download/0100d62924bee7854f0ab810e302bbee9405.png)

```
import kd.bos.openapi.api.plugin.ApiSavePlugin;

import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class DemoApiSavePlugin implements ApiSavePlugin {

	@Override
	public List<Map<String, Object>> preHandleRequestData(List<Map<String, Object>> reqData) {
		List<Map<String, Object>> updatedData = new ArrayList<>(reqData.size());
		for (Map<String, Object> entry : reqData) {
			Map<String, Object> newEntry = new LinkedHashMap<>(entry.size());
			// 先放入先触发的 字段
			Object checkboxfield = entry.remove("xxx");
			if (checkboxfield != null) {
				newEntry.put("xxx", checkboxfield);
			}
			newEntry.putAll(entry);
			updatedData.add(newEntry);
		}
		return updatedData;
	}
}
```
