# RESTful API 日志

# 1 简介

## 1.1 功能介绍

RESTful API 日志功能用于记录 API 调用全链路信息，支持日志查看、筛选与导出，核心功能包括：

- 多维度日志记录：记录 API 调用的基础信息（调用时间、调用者、客户端 IP）、请求信息（请求方法、资源路径、请求参数）、响应信息（HTTP 状态码、响应参数、错误信息）及性能信息（API 耗时、业务处理耗时），日志级别分为 “不记录”“基本日志”“详细日志”“大文本日志”（控制出入参截取长度）；
- 精准筛选能力：支持按 “调用时间”（如过去 1 小时、自定义日期范围）、“API 编码 / 名称 / URL”、“调用状态”（成功 / 失败）、“HTTP 状态码”（如 200、400）筛选日志，快速定位目标记录；
- 日志详情查看：点击单条日志可查看完整信息。

## 1.2 应用场景

- 故障溯源：API 调用失败时（如生产环境中采购订单创建 API 返回 500 错误），通过日志查看详细错误信息（如 “数据库连接超时”）与调用上下文（如调用者 IP、传入的billno），快速定位故障原因；
- 审计合规：金融、政务等对数据合规性要求高的行业，通过日志记录 API 调用的 “谁（调用者）、何时（调用时间）、做了什么（操作类型）、结果如何（响应状态）”，满足审计要求（如追溯某笔订单的创建操作记录）；
- 性能优化：通过日志中的 “API 耗时” 字段，统计耗时较长的 API，分析是否因参数设计（如未分页）或业务逻辑（如关联表过多）导致性能问题，辅助优化。

## 1.3 系统路径

【开放服务云】→【OpenAPI】→【RESTful API】→【RESTful API 日志】

关联入口：在 RESTful API 管理列表中，选中目标 API，点击操作列的【日志】按钮，自动跳转至该 API 的专属日志列表页（已筛选该 API 的调用记录）。

## 1.4 字段 / 按钮说明

### 1.4.1 字段说明

| **字段名** | **字段说明** |
| --- | --- |
| 调用状态 | RESTful API 调用最终状态 |
| HTTP 状态码 | API 返回的 HTTP 状态码，如 “400” |
| URL | RESTful API 调用的统一资源定位符 |
| 编码 | API 编码 |
| 名称 | API 名称 |
| 请求方法 | HTTP 方法，如GET/ POST/PUT /PATCH/DELETE |
| 调用时间 | API 开始调用的时间 |
| 结束时间 | API 调用结束的时间 |
| API 耗时 (ms) | API 调用所花费的时间 |
| 调用客户端 IP | 发起 API 调用的客户端 IP 地址 |
| TraceId | 用于链路追踪的唯一标识 |
| 第三方应用 | 调用 API 的第三方应用名称 |
| 调用者 | 发起 API 调用的用户 |
| 请求参数 | API 调用时传入的参数，包含路径参数、查询参数、请求体参数、请求头参数等，可点击 “查看” 查看完整内容 |
| 响应参数 | API 调用返回的响应数据，包含错误类、错误码、错误信息等，可点击 “查看” 查看完整内容 |

### 1.4.2 操作按钮

【导出日志】：点击按钮，导出当前RESTful API日志。

# 2 主要操作

## 2.1 自定义API日志级别

管理员可以通过OpenAPI系统参数，来定义记录不同级别的API日志和日志保留天数。

1）配置API日志级别

路径：基础服务云 → 公共设置 → 参数配置 → 系统参数，在OpenAPI参数中，可以配置不同的API日志级别，包含基本日志、详细日志和大文本日志等。用户按需勾选需要的日志级别，并维护日志保存天数。

备注：大文本日志默认截取请求参数和返回参数前10000字符，私有云租户可通过MC参数“api_fullPayloadLog”（默认false），将该参数设为true后，即可完整记录日志请求和返回参数。

特别声明：若MC配置了记录全部入参数据参数，可能会导致系统API调用缓慢，并且日志量暴增，极端场景下会有OOM的风险，用户需严格控制相关接口的并发调用。

## 2.2 查看RESTful API调用日志

打开RESTful API日志列表界面，在这里可以看到RESTful API日志调用记录，包含调用状态、HTTP状态码、URL、编码、名称、请求参数、响应参数、调用时间、traceid等信息。

备注：日志默认保留30天，到期自动清理。

## 2.3 导出API日志

若需留存该失败日志用于汇报或分析，勾选目标日志，点击列表页顶部的【导出日志】按钮，查看txt 格式的API日志。
