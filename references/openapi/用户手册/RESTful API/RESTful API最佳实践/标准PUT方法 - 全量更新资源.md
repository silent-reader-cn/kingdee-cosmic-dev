# 标准PUT方法 - 全量更新资源

## 1 接口介绍

将业务对象的全量更新操作发布为RESTful API，通过资源唯一标识（如 ID）定位资源，传入完整资源数据覆盖原有信息，适用于需修改资源所有字段的场景（如采购订单所有信息变更后同步更新）。

## 2 接口示例

点击“快速创建”或“新增”按钮，新增RESTful API，“操作类型选择“更新”，“操作选择“全量更新”。

- 实体信息：业务对象、操作类型和操作会根据创建向导中的配置自动带出；
- **维护基本信息：**名称：录入 “全量更新采购订单（需体现业务语义）”编码：系统自动生成，支持手工修改；所属应用：按业务对象关联自动带出；日志级别：默认记录基本日志，可选择 “详细日志”（记录出入参，便于故障排查）；详细描述：手工录入，如“全量更新采购订单，含单据基本信息与物料明细”；
- **请求端点配置：**方法：PUT资源路径：系统自动生成，支持修改；路由唯一标识：系统自动拼接。完整请求地址：系统自动拼接。
- **维护请求参数：**Path 参数：默认为资源的唯一标识，也就是主键“id”，字段类型为 “long”，系统自动生成示例值。请求体：根类型 “对象”，添加业务对象所有关键字段，需传入完整资源数据（未传入字段将写入默认值）；若请求体包含分录字段（如billentry），PUT 请求会强制覆盖原有分录，避免数据残留。
- **维护响应参数：**成功时返回状态码 “200-OK”，返回id（更新资源 ID）和modify_time（更新时间）；异常状态码如“400- Bad Request”或“500-Internal Server Error”，接口会返回对应错误信息。

点击 “保存”并“启用”，API 可对外调用；用户在获取到请求令牌后，可通过完整请求地址，传入完整订单数据，完成订单的全量更新。

备注：若需批量更新，在 “数据模式” 选择 “批量”，请求体根类型变为 “数组”，请求体传入多条资源对象，同时需要在请求体中传入唯一资源标识id。
