# 自定义方法 - 提交、审核资源

## 1 接口介绍

将业务对象的非 CRUD 操作（如单据提交、撤销、审核、反审核）发布为RESTful API，适用于外部系统触发苍穹业务流程状态变更的场景（如电商平台需要将采购订单改为 “已提交” 状态）。

说明：当操作意图无法通过 HTTP 标准请求方法（如 GET/POST/PUT/DELETE 等）直接表达时，此类方法属于自定义方法。为保证兼容性与规范性，建议统一使用 POST 作为该类自定义方法的请求方式。

## 2 接口示例

列表点击“新增”按钮，新增RESTful API，“操作类型选择“状态变更”，“操作选择“提交”。

- **实体信息：**业务对象、操作类型和操作会根据创建向导中的配置自动带出；
- **维护基本信息：**名称：录入“提交采购订单（需体现业务语义）”；编码：系统自动生成，支持手工修改；所属应用：按业务对象关联自动带出；日志级别：默认记录基本日志，可选择 “详细日志”（记录出入参，便于故障排查）；详细描述：手工录入，如“根据主键提交采购订单”。
- **请求端点配置：**方法：POST资源路径：系统自动生成，支持修改；路由唯一标识：系统自动拼接。完整请求地址：系统自动拼接。
- **维护请求参数：**仅需 Path 参数，默认为资源的唯一标识，也就是主键“id”，字段类型为 “long”，系统自动生成示例值。
- **维护响应参数：**成功状态码 “200-OK”，返回id和modify_time（状态变更时间）；异常提示：若资源已提交，返回 400 错误 “只有暂存的数据才允许提交”。

点击 “保存”及“启用”按钮，API 可对外调用；用户在获取到请求令牌后，可通过完整请求地址，传入path参数，完成订单的提交操作。

其他状态变更配置如 “审核”，则在操作选择“审核”，资源路径变为/pm_purorderbill/{id}/audit，配置逻辑与“提交”一致。

注意：若需批量提交，选择 “数据模式：批量”，请求方式仍为 “POST”，请求体传入需提交的id列表（如{"id":["2184074116397546496","2184074116397546497"]}）
