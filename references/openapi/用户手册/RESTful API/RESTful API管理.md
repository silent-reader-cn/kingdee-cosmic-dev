# 1 简介

## 1.1 功能介绍

RESTful API 是金蝶AI苍穹开平台基于 REST 规范打造的新版 API 开发引擎，核心功能覆盖全生命周期管控与标准化设计，具体包含：

- 全生命周期管理：支持从 API 设计、创建、测试、发布到禁用的一站式管控，内置 RESTful API 规范校验，确保接口设计合规。
- 标准化操作支持：遵循 RESTful规范，通过 GET/POST/PUT/PATCH/DELETE 等标准化 HTTP 方法实现资源的CURD操作，统一资源路径、请求/响应格式及 HTTP 状态码。
- 两种开发模式：支持 “实体服务”（基于业务对象零代码配置）和 “自定义脚本”（脚本调用插件方法，处理复杂业务场景）。
- 安全与兼容性保障：支持权限管控、日志脱敏，并发量与请求/返回数据量大小控制；保障API向后兼容，业务逻辑变动不影响接口调用，适配全球化业务需求。

## 1.2 应用场景

- 企业内部系统集成：实现 ERP 与 CRM、库存管理等系统间的数据交互，如通过 API 同步采购订单、客户信息等数据。
- 第三方开发者对接：为外部应用提供标准化接口，如电商平台调用采购 API 创建订单、财务软件调用凭证 API 生成财务凭证等。
- 全球化业务对接：符合国际通用 REST 规范，降低海外开发者接入门槛，适配不同地区技术生态与用户习惯，助力企业出海。

## 1.3 系统路径

路径：【开放服务云】→【OpenAPI】→【RESTful API】→【RESTful API 管理】

## 1.4 字段 / 按钮说明

### 1.4.1 字段说明

| **字段分类** | **字段名** | **字段说明** |
| --- | --- | --- |
| 实体信息 | 业务对象 | 实体服务 API 关联的业务对象（如 “采购订单”“客户”“物料”） |
| 操作类型 | 系统预置，包括 “查询”“新增”“更新”“删除”“状态变更” |  |
| 操作 | 具体功能操作，如 “详情查询”“列表查询”“全量更新”“部分更新”“提交”“审核”等 |  |
| 分录标识 | 新增/删除分录时关联的子资源（如 “物料明细”“费用明细”），从业务对象自动带出 |  |
| 基本信息 | 名称 | 手工录入，描述 API 功能（如 “查询采购订单详情”“新增采购订单”） |
| 编码 | 系统自动生成，支持手工修改 |  |
| 所属应用 | 根据关联业务对象自动带出（如 “采购管理”“总账”） |  |
| 服务类型 | 分为 “实体服务”（基于业务对象）和 “自定义脚本”（手工开发脚本） |  |
| 日志级别 | 可选 “不记录”“基本日志”（无出入参）“详细日志”（出入参截取 2000 字符）“大文本日志”（出入参截取 10000 字符），默认使用系统配置 |  |
| 自定义分组 | 按业务场景归类 API（如 “电商集成API”“财务同步 API”），支持手工创建与调整 |  |
| 请求端点配置 | 请求方法 | 遵循 HTTP 语义：GET（查询）、POST（新增 / 状态变更）、PUT（全量更新）、PATCH（部分更新）、DELETE（删除） |
| 资源路径 | 系统自动生成，格式如 “/pm_purorderbill/{id}”，支持手工修改 |  |
| 路由唯一标识 | 由 “请求方式 + 开发商标识 + 所属应用 + 资源路径模式串” 组成（路径参数转为 p0、p1...），确保路由唯一性 |  |
| 完整请求地址 | 包含环境地址的完整 URL，如 “[https://feature.kingdee.com:1026/deviai/kapi/v3/kdtest/pm/pm_purorderbill”](https://feature.kingdee.com:1026/deviai/kapi/v3/kdtest/pm/pm_purorderbill”) |  |
| 请求参数 | Path 参数 | 路径参数，用于定位资源（如“{id}”为资源唯一标识、“{billentry_id}” 为分录唯一标识） |
| Query 参数 | 查询参数，用于过滤、分页（如 “offset=0”（起始位置）、“limit=10”（每页条数）、“createtime=2025-06-01”（创建时间过滤）） |  |
| 请求体 | POST/PUT/PATCH 请求的入参，JSON 格式，可从业务对象选择字段或手工添加 |  |
| 操作参数 | 如 “是否触发引入方法”，用于配置 API 调用特殊规则，支持选择默认参数 |  |
| 响应参数 | HTTP 状态码 | 系统预置：200-OK（成功）、201-Created（创建成功）、400-Bad Request（参数错误）、404-Not Found（资源不存在）、500-Internal Server Error（服务错误） |
| 参数名称 / 类型 | 响应字段名与数据类型（如 “id” 为 long 型、“create_time” 为 datetime 型、“billno” 为 string 型） |  |
| 示例值 | 字段示例数据，长日期 datetime 类型示例值为零时区日期（如 “2025-04-08T07:16:45.750Z”） |  |

### 1.4.2操作按钮

【快速创建】：点击按钮，弹出快速创建窗口，支持快速将业务对象发布成为RESTful API；

【新增】：点击按钮，弹出新增向导窗口，选择业务对象、操作类型、数据模式和操作；

【新增自定义脚本API】：点击按钮，打开自定义脚本API维护页面；

【升级】：点击按钮，支持勾选存量接口，升级为符合REST规范的RESTful API；

【删除】：仅支持勾选单条或多条API，点击按钮，删除API；

【启用】：点击按钮，启用API；

【禁用】：点击按钮，禁用API；

【API测试】：点击按钮，弹出API文档页面（Swagger),支持进行在线测试；

【导出API】：导出API信息，合并为一个dts文件。

【导出ZIP】：支持勾选多条API文件导出生成压缩包，每条API信息为一个dts文件。

【导入API】：打开导入API弹窗，支持批量导入API信息。

【云更新】：支持从资源云环境同步最新的原厂标准RESTful API。

【日志】：点击按钮，自动跳转到API日志界面，展示所选API的日志信息。

【刷新】：刷新当前列表页面。

# 2 主要操作

## 2.1 打开RESTful API 管理列表

进入RESTful API管理列表，路径：【开放服务云】→【OpenAPI】→【RESTful API】→【RESTful API 管理】，列表默认按 “云 - 应用” 分组展示 API（如 “供应链云 - 采购管理”“基础服务云 - 企业建模”）。

- 筛选与搜索：按时间筛选：顶部 “调用时间” 默认筛选 “过去三个月” 的 API，可自定义时间范围缩小范围；精准搜索：在搜索框输入 “API 编码 / 名称 / URL”，快速定位目标 API；高级过滤：点击 “展开过滤”，可按 “API 状态”（启用 / 禁用 / 内测）、“所属应用”（如 “采购管理”“总账”）进一步筛选。
- 自定义分组：点击左侧树 “自定义分组”→“新增”，输入分组名称（如 “2025 电商对接 API”）；勾选目标 API，选择自定义分组，点击确认完成归类，方便按业务场景管理 API。
- 批量操作：批量启用 / 禁用：勾选多条 API，点击 “启用” 或 “禁用”，批量修改 API 状态；
- 导入 / 导出：点击 “导出 ZIP”，批量导出多条 API 为 ZIP 包（每条 API 为 dts 文件）；点击 “导入 API”，选择本地 dts 文件或 ZIP 包，批量导入 API 配置。

## 2.2 RESTful API 最佳实践

产品可以基于预置模板快速生成符合 REST 规范的 CRUD 接口（如详情查询、列表查询、新增资源），大幅缩短 API 开发周期，确保全平台 API 风格统一、文档规范可维护。打开快速创建弹窗，在 RESTful API 管理列表点击 “快速创建”，弹出 “RESTful API 最佳实践”。

![上传图片](https://vip.kingdee.com/download/01006e7e9065f09f47a4b5e2d5af70a95139.png)

基于最佳实践模板，为用户自动生成符合 RESTful 规范的 CRUD 接口（如 GET /user/{id}、POST /order）

自动生成 API 基本信息（如名称、描述）、请求端点（Endpoint）、请求/响应参数示例，用户仅需微调即可发布，提升标准接口开发效率。同时接口天然支持国际化多语言和跨时区调用，快速实现异构系统间跨地域集成对接。

注意：基于业务对象快速生成的 RESTful API，在第三方系统持 token 发起请求时，除基础的组织权限、数据规则控制外，系统将自动校验token中的代理用户，是否包含对应业务对象的访问许可，以此强化接口安全防护。

## 2.3 新增 RESTful API

在 RESTful API 管理列表点击 “新增”按钮，弹出弹出 “RESTful API 创建向导”页面。

选择配置项：

- 业务对象：通过弹窗 F7 选择目标业务对象（如 “采购订单”“客户”等）；
- 操作类型：选择 “查询”“新增”“更新”“删除”“状态变更”（如 “查询”、新增等）；
- 数据模式：选择 “单条” 或 “批量”；
- 操作：选择具体功能（如 “详情查询”、“列表查询”）。

确认后，跳转至 API 编辑页，用户可编辑API 基本信息（如名称、描述）、请求端点（Endpoint）、请求/响应参数等详细信息，然后点击 “保存”，API 创建完成。
