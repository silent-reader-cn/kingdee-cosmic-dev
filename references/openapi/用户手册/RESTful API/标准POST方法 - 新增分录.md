# 标准POST方法 - 新增分录

## 1 接口介绍

为主资源（如采购订单）新增子资源（如物料明细分录）的操作发布为 RESTful API，适用于外部系统补充主资源关联子资源的场景（如为采购订单添加新的物料明细）。

## 2 接口示例

列表点击“新增”按钮，新增RESTful API，“操作类型选择“新增”，“操作选择“新增分录”。

- **实体信息：**业务对象、操作类型和操作会根据创建向导中的配置自动带出，手工选择需要新增的实体对象的分录标识，如物料明细（billentry）；
- **维护基本信息：**名称：录入“新增采购订单物料明细分录信息（需体现业务语义）”；编码：系统自动生成，支持手工修改；所属应用：按业务对象关联自动带出；日志级别：默认记录基本日志，可选择 “详细日志”（记录出入参，便于故障排查）；详细描述：手工录入，如“新增采购订单物料明细分录信息”。
- **请求端点配置：**方法：默认POST资源路径：系统自动生成，支持修改；路由唯一标识：系统自动拼接。完整请求地址：系统自动拼接。
- **维护请求参数：**Path 参数：默认为资源的唯一标识，也就是主键“id”，字段类型为 “long”，系统自动生成示例值。请求体：根类型 “对象”，仅支持勾选分录标识（物料明细）关联的字段，如物料分录id，物料编码、单价等。
- **维护响应参数：**成功返回 “201-Created”，包含子资源id和create_time；异常返回 404（主资源 / 分录不存在）。

保存并启用后，用户在获取到请求令牌后，可通过完整请求地址，传入分录信息，完成订单的追加分录操作。

注意：若需批量新增分录，在 “数据模式” 选择 “批量”，请求方式改为“POST”，请求体根类型变为 “数组”，在请求Path参数中传入主资源id，请求体传入多条子资源对象。
