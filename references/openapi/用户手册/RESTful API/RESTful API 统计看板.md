# 1 简介

## 1.1 功能介绍

- 为 API 运维及开发人员提供直观监控看板，可实时查看调用量、失败数、成功率、平均响应时间等核心指标；
- 支持按第三方应用、RESTful API、时间筛选，通过趋势图和排行直观呈现API运行状态，帮助快速发现异常与性能问题。

## 1.2 应用场景

实时监控RESTful API调用量、响应时间等，及时发现异常流量等问题。 帮助用户定位慢接口、高错误率接口，针对性优化，同时识别热门或异常调用的客户端。

## 1.3 系统路径

【开放服务云】→【OpenAPI】→【RESTful API】→【RESTful API 统计看板】

# 2 主要操作

## 2.1 查看RESTful API统计看板

以 “查看与第三方系统‘OA系统’对接过程中，RESTful API 一段时间的运行情况，定位失败率高、响应慢的 API 并分析原因” 为例，演示看板查看与分析流程。

默认展示全量 API 的统计数据。

- 设置筛选条件：筛选应用相关 API：点击 “RESTful API 筛选框”→选择 “按第三方应用筛选”→在弹窗中勾选 “OA”→点击 “确定”，仅展示该外部系统调用的RESTful API；选择时间范围：在 “调用时间” 下拉框中选择自定义，并选择日期范围；执行筛选：点击 “查询” 按钮，看板数据刷新为 “第三方应用OA下所有 API 在一段时间范围” 的统计结果。
- 查看核心指标，初步判断健康度：① 查看 “API 调用成功率”：若成功率低于 90%（如显示 “82%”），说明存在较多调用失败问题；② 查看 “状态码类型卡片”：若 “4xx - 客户端错误” 次数较多（如 50 次），可能是第三方调用参数错误；若 “5xx - 服务端错误” 较多（如 30 次），需排查服务端问题；③ 查看 “平均响应时间”：若平均耗时超过 1500ms（如 “1800ms”），需关注性能瓶颈。④ 分析趋势图，识别异常时段：⑤ 查看 “API 调用趋势图”：重点关注失败次数曲线的波动（如某一天 14 点失败次数突然上升至 10次），记录异常时段；⑥ 关联响应时间：若异常时段内平均响应时间同步上升（如从 800ms 升至 3000ms），可能是该时段调用量激增导致服务过载。⑦ 通过排行表定位问题 API：⑧ 查看 “API 失败率排行表”：找到失败率最高的 API，记录其名称与资源路径；⑨ 查看 “API 响应时长排行表”：找到平均耗时最长的 API，标记为性能优化重点；⑩ 钻取详情，定位具体原因：⑪ 分析失败 API：点击API名称，可跳转至该 API 的日志，查看 日志响应参数中的具体“失败原因”，并判断是否可以优化接口逻辑；若日志耗时过长，需要查看更详细日志信息，可以进入到Monitor环境，根据RESTful API日志中记录的traceid，去查询更明细的日志信息。
